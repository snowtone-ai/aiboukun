作成日：2026-05-31

# 0. 最重要コンセプト

## 一言定義

**アイボウくんは、店舗オーナーの代わりにGoogleマップ集客を見張り、口コミ返信・低評価検知・競合比較・改善提案・週次/月次レポート作成まで行う、月1万円で雇えるAI相棒。**

---

## プロダクトの本質

これは「管理ツール」ではない。  
これは「Googleマップ集客のAI担当者」である。

```text
従来のSaaS：
ユーザーがログインする
画面を探す
数字を見る
意味を考える
自分で作業する

アイボウくん：
AIが常時監視する
重要な変化だけ知らせる
今やるべきことを提案する
必要なページやレポートを即時生成する
返信・改善・報告を代行する
```

---

## 導入イメージ

ユーザーに伝えるべき価値は以下。

```text
マーケティング担当者を1人雇う代わりに、
Googleマップ集客を見てくれるAI相棒を月1万円で雇う。
```

価格訴求は「ツール利用料」ではなく「人件費代替」である。

# 1. プロダクト思想

## 1.1 管理画面を中心にしない

アイボウくんのUIは、既存SaaSのように「ダッシュボードの集合」にしない。  
最初の画面は、**アイボウくんに話しかける画面**にする。

ユーザーは以下のように操作する。

```text
「今月のレポート見せて」
「悪い口コミだけまとめて」
「新宿店と渋谷店を比較して」
「今週やるべきことを3つ出して」
「未返信の口コミに返信案を作って」
「評価が下がっている店舗を教えて」
「競合に負けている理由を教えて」
```

AIは、該当ページに移動するか、その場でレポートを生成する。

---

## 1.2 スマホファースト

店舗オーナー・店長はPCの前に座って管理画面を見るとは限らない。  
そのため、スマホから短時間で使えることを前提にする。

重要設計：

```text
チャットで操作できる
音声で操作できる
通知から即返信できる
レポートをスマホで読める
長い表ではなく要点を3つに絞る
ボタンは「承認」「修正」「あとで」「詳しく見る」を基本にする
```

---

## 1.3 使用コストを限界まで下げる

アイボウくんの価値は、機能数ではなく、使用コストの低さである。

```text
見なくてよい
探さなくてよい
考えなくてよい
文章を書かなくてよい
レポートを作らなくてよい
```


# 5. 業種方針

## 5.1 共通基盤 + 業種パック

プロダクト自体は共通で作る。  
ただし、業種ごとに口コミ属性・返信トーン・NG表現・改善提案テンプレートを持つ。

```text
共通OS
├─ 飲食パック
├─ 美容室パック
├─ 歯科パック
├─ 美容クリニックパック
├─ 整体・接骨院パック
├─ ホテル・旅館パック
└─ 小売・サービス業パック
```

---

## 5.2 業種別の重要属性

| 業種 | 重要な口コミ属性 |
|---|---|
| 飲食 | 味、価格、接客、待ち時間、清潔感、席、雰囲気、子連れ、予約 |
| 美容室 | 技術、仕上がり、カウンセリング、指名、接客、待ち時間、価格 |
| 歯科 | 説明、痛み、不安軽減、先生の対応、スタッフ対応、清潔感、待ち時間 |
| 美容クリニック | 効果、価格、勧誘、説明、術後対応、リスク説明、プライバシー |
| 整体・接骨院 | 効果、説明、通いやすさ、価格、雰囲気、先生の対応 |
| ホテル | 清潔感、立地、接客、朝食、騒音、設備、価格、チェックイン |
| 小売 | 品揃え、接客、価格、在庫、アクセス、駐車場 |

---

## 5.3 医療・美容医療は特別扱い

医療・美容医療は、通常業種よりも返信・表現リスクが高い。  
専用パックでは、以下を必須にする。

```text
医療広告ガイドライン配慮
薬機法・景表法リスク表現検知
治療効果を断定しない返信
個別症状に踏み込みすぎない返信
体験談の広告利用リスクへの注意
```

## 6.2 口コミ返信AI

### 基本機能

```text

AIが返信案を生成
ユーザーが承認・修正
Google口コミへ返信
修正差分を学習
```

### 承認ON/OFF設計

単純な自動返信ON/OFFではなく、リスク別に設定する。

| 口コミタイプ | 推奨動作 |
|---|---|
| 星5・短文 | 自動返信ON可 |
| 星4・通常 | 自動返信ON可 |
| 星3 | 承認推奨 |
| 星1〜2 | 必ず承認 |
| 医療・法務・炎上リスクあり | 必ず承認 |
| 個人名・返金・事故・クレーム | 必ず承認 |

# 10. AIプロバイダ設計

## 10.1 開発時

開発時は、**Gemini API**を使用する。  
無料枠・制限内で開発する。

ただし、無料枠・レート制限・モデル提供状況は変動するため、Geminiに密結合しない。

参考：
- Gemini API Pricing: https://ai.google.dev/gemini-api/docs/pricing
- Gemini API Rate limits: https://ai.google.dev/gemini-api/docs/rate-limits
- Gemini API Billing: https://ai.google.dev/gemini-api/docs/billing

---

## 10.2 事業化時

事業化時は、有料APIに差し替える。  
Gemini、OpenAI、Anthropic、その他LLMを切り替え可能にする。

### 必須設計

```text
LLM Provider Adapterを作る
モデル名を環境変数で切り替える
プロンプトをDBまたは設定ファイルで管理
出力JSONスキーマを固定
プロバイダ別の失敗時リトライを実装
コスト計測ログを保存
```

### Adapter例

```ts
interface LLMProvider {
  generateText(input: GenerateTextInput): Promise<GenerateTextOutput>
  generateJson<T>(input: GenerateJsonInput): Promise<T>
  classify(input: ClassifyInput): Promise<ClassifyOutput>
}
```

```text
Claude Proプラン使用可能
```
