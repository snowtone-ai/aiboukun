# vision.md -- Product North Star

## Purpose

アイボウくんは、店舗オーナーの代わりにGoogleマップ集客を見張り、口コミ返信・低評価検知・競合比較・改善提案・週次/月次レポート作成まで行う、Googleマップ集客の営業・マーケティング担当AIエージェントである。

「管理ツール」ではなく「月1万円で雇えるAI相棒」。

---

## Target Users

### 個人店オーナー
- 忙しくマーケティング専任者がいない
- Googleマップ管理は重要だが後回し
- 口コミ返信が面倒で低評価が怖い
- 数字の分析が苦手
- 刺さる価値: AIが代わりに見てくれる / 月1万円でマーケ担当を雇う感覚

### 店長
- 現場業務で忙しく口コミ返信が後回し
- 本部からのレポート要求が面倒
- 悪い口コミへの対応が不安
- 刺さる価値: 返信案をAIが作る / 本部向け報告を自動生成

### 多店舗本部
- 店舗ごとの対応品質にばらつき
- 低評価店舗の発見が遅い
- 月次レポート作成が重い
- 刺さる価値: 全店舗を一括監視 / 本部向けレポート自動作成

---

## Success Criteria

- Google連携後3分以内に初回価値を提示できる
- 未返信口コミ数を可視化できる
- 低評価リスクを自動検知できる
- AI返信案を即生成できる
- 今週やるべきことを3つに絞って提示できる
- 店舗オーナーがスマホで1分以内に判断できる
- チャット/ボイスで主要操作が完結する

---

## Non-goals

以下には踏み込まない:

- POS連携の深い代替
- 予約台帳の代替
- LINE配信全般
- CRM全機能
- 広告運用
- 在庫・勤怠・決済・会計・給与・シフト管理

「接続」はしてよいが「代替」はしない。

---

## Product Principles

1. **AIが担当者である** -- ユーザーが管理画面を探すのではなく、AIが先に動く
2. **スマホファースト** -- スマホで1分以内に確認・承認できる
3. **使用コスト最小** -- 見なくてよい / 探さなくてよい / 考えなくてよい / 文章を書かなくてよい
4. **Human-in-the-loop** -- 重要な実行（低評価返信・法務リスク）は必ず承認を挟む
5. **チャット/ボイス中心** -- 最初の画面はアイボウくんとの会話画面
6. **店舗Ontology** -- 企業 > ブランド > エリア > 店舗の階層構造でデータを管理
7. **親しみやすさ** -- かわいいが幼稚ではない / 丁寧だが堅すぎない口調

---

## Primary User Flows

### フロー1: 毎朝の確認（1分）
1. アプリを開く
2. アイボウくんの今日の報告を受け取る
3. 重要アラートを確認
4. 未返信口コミに返信案を承認 or 修正

### フロー2: 口コミ返信
1. 通知から口コミを開く
2. AI返信案を確認
3. 承認 / 修正してから承認
4. Googleに自動投稿

### フロー3: チャット操作
1. 「今月のレポート見せて」と入力
2. AIがレポートを即生成・表示
3. 「来月やるべきことを3つ出して」
4. AIが改善タスクを提示

### フロー4: 多店舗本部確認
1. 全店舗サマリーを確認
2. 要注意店舗にフォーカス
3. 月次レポートを自動生成
4. 本部向けにエクスポート

---

## Failure Cases

- Google API制限 / OAuth期限切れ → ユーザーに通知 / リトライ
- LLM生成失敗 → 再生成 / ユーザーへの手動返信を促す
- 低評価口コミが自動投稿される → 絶対に防ぐ（Human-in-the-loop）
- 医療・法務リスクを見逃す → リスク検知を多段階で実施
- テナント間でのデータ漏れ → 組織IDによる厳密な分離

---

## Long-term Goal

Googleマップ集客の事実上の標準AIエージェントになる。

AIO（AI Overview）/ Ask Maps時代において、口コミ属性が検索推薦に影響する中で、アイボウくんが店舗の集客力を継続的に改善するインフラになること。
